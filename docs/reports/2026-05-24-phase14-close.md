## 5. Known limitations / Phase 15 への送り

### 5-A. CLI 統合
- `harness project import / edit / show / history / diff / export`
- `harness policy import / edit / compile / export`
- `harness knowledge import --from-docs / edit / show / history / diff
  / export`
- `harness assets status / export --all / import --from-files / reconcile`

repository は揃ったので CLI wrap は機械的作業。Phase 15-2 〜 15-4 で
operations table と統合して audit する。

### 5-B. Runtime resolution DB-first 切替
- `loadProjectProfile` (現状 file から読む) → DB-first + file fallback
- `loadRepoPolicy` (file から読む) → DB-first
- knowledge digest (file から読む) → DB-first

これらは loader test の large 修正を伴うため、Phase 14 では deferred。
Phase 15 で `HARNESS_ASSET_SOURCE=db` をデフォルトに切替、`=file` を
explicit fallback として残す。

### 5-C. Compat export loop
`recordAssetExport` で row は track できるが、実際に file を書き出す
loop (3 種 asset × 全 current revision) は Phase 15 で `harness assets
export --all` と統合。

### 5-D. Operation audit integration (Phase 13 連携)
`project.edit` / `policy.edit` / `knowledge.edit` operation types を
Phase 13 OperationRunner で wrap して audit に残す。Phase 15 で CLI
edit 経路 + dashboard mutation を同時 integrate。

### 5-E. Knowledge digest との関係
`knowledge_entries.body` (Phase 6 NOT NULL) と
`knowledge_entry_revisions.body_markdown` の両方が存在する状態。Phase
14 では auto-INSERT 経路で `body=''` を渡しているが、既存 digest 経路
は `knowledge_entries.body` を読む。Phase 15 で digest の DB-first 切替
時に `body` 列を deprecate / 削除検討。
