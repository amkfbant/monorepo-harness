## 5. Known limitations / Phase 16 + post-Phase-15 への送り

### 5-A. CLI 統合

各 sub-phase の CLI が未統合 (repository は揃った):
- `harness db doctor [--json] [--category]`
- `harness db repair [--check <id> | --all-repairable] [--apply]`
- `harness db backup [--name] [--rotate N]` + list / verify / restore
- `harness db archive --before <date>` + archives list/attach/detach
- `harness db stats snapshot / delta --from <id> / --since 7d`
- `harness db upgrade-check --target <phase> [--json]`

repository が揃っているので CLI wrap は機械的。post-Phase-15 で
Phase 14 deferred asset CLI と一緒にまとめて land。

### 5-B. Phase 14 deferred asset CLI

Phase 14 close report §5 で deferred な:
- `harness project / policy / knowledge import / edit / show / history
  / diff / export`
- `harness assets status / export --all / import / reconcile`

これらは Phase 14 repository (project_profile_revisions /
policy_templates / knowledge_entry_revisions / asset_exports) と
Phase 15-2 doctor (`assets.dirty_export` check) を組み合わせれば実装
できる。本 close 時点では未統合。post-Phase-15 work。

### 5-C. 実 archive build

archive_catalog のみで、実 archive DB build (copy-only / move +
integrity_check + run/blob row 移し) は scope 大きく Phase 15 では
含まず。post-Phase-15 で Phase 16 blob external storage と統合して
扱う (古い blob を archive DB + external store に分散)。

### 5-D. Doctor check の拡張

Phase 15-2 minimum 6 fixtures。追加候補:
- `runtime.legacy_file_rows` (Phase 9-11 gate と alias)
- `consensus.orphan_overrides` (Phase 11-6 review_overrides 整合性)
- `operations.long_running` (Phase 13 operations.status='running' で
  age > N min)
- `blob.sha_mismatch` (Phase 16 storage 検証時に必要)

post-Phase-15 で increment。

### 5-E. Runtime loader DB-first (Phase 14 残し)

Phase 14 で deferred な runtime profile / policy / knowledge resolution
の DB-first 切替も post-Phase-15。Phase 15 は infrastructure ready
のみ提供。

### 5-F. CORS preflight (Phase 12 post-close 残し)
