## Implemented Surface

- `harness mcp serve --transport stdio` JSON-RPC MCP server.
- `harness mcp tools/resources/prompts/config/sessions/invocations/confirmations`.
- Read tools for projects, domains, policy snapshots, runs, artifacts, review, backlog, knowledge, DB/doctor, and operation audit.
- Operation audit read tools redact idempotency keys, inputs, results, metadata, event payloads, and error messages before returning through MCP.
- Resources for project/run/artifact/backlog/knowledge/DB/doctor/operation context.
- Prompts for project inspection, backlog planning, run review/summarization, and rerun preparation.
- Dry-run tools for project check, run preview, cleanup preview, PR preview, DB repair/archive/blob migration preview.
- Guarded mutations for run/review/rerun/backlog/knowledge via `OperationRunner`.
- Dangerous mutations return `confirmation_required` and execute only through `harness operation confirm`.
- DB-backed mutation/run/concurrency budgets and idempotency replay.
- MCP config resolution covers `--config`, `.harness/mcp.yaml`, project profile `mcp` sections, then safe defaults.
- Explicit missing `--config` fails closed, and confirmations persist the MCP permission snapshot used to create the preview.
- MCP permission identity is launch-controlled (`--client-name` / `MCP_CLIENT_NAME`) and cannot be upgraded by self-reported `initialize.clientInfo`.
- `review.process`, `pr.create`, and `db.archive.apply` now bind confirmation previews to the execution path: review processing uses active proposal id/source hash, PR creation reuses the run base branch, and full DB archive apply requires global MCP scope.
- Confirmation handler failures consume the request with a redacted error instead of leaving it stuck in `confirmed`.
- MCP session/tool invocation audit with argument hashes, redacted arguments, redacted error messages, confirmation/operation correlation, and redacted confirmation listings.
