## 5. Known limitations

### 5-A. S3 adapter (deferred)

local adapter で migration / verify / GC を test 可能。S3 adapter
(BlobStore interface 実装) は dependency 追加 + IAM 設計 + mocked
test 環境が必要で scope 大。post-Phase-16 work。

### 5-B. artifacts.storage CHECK 緩和 (schema v12)

`artifacts.storage CHECK IN ('file', 'db')` は v8 hard 制約。SQLite
で CHECK を ALTER できないため、artifacts table を rebuild する
schema v12 が必要:

1. CREATE TABLE artifacts_new (... CHECK (storage IN ('file', 'db', 'external')))
2. INSERT INTO artifacts_new SELECT * FROM artifacts
3. DROP TABLE artifacts; ALTER TABLE artifacts_new RENAME TO artifacts
4. recreate indexes / triggers

schema v12 migration を post-Phase-16 で land すれば、Phase 16 infra
を実用化できる (`migrateBlobsToExternal` の最後で `UPDATE artifacts
SET storage='external' WHERE blob_sha256 = ?` を追加)。

### 5-C. backup / archive integration (16-7 deferred)

backup_catalog.manifest_json に external store summary を含める
helper、archive 時の store config snapshot などは Phase 16-7 で
扱う予定だったが、infrastructure-only scope で post-Phase-16 work。

### 5-D. CLI 統合

すべての CLI (`harness db blob-stores add-local/list/test`,
`harness db migrate-blobs`, `harness db verify-blobs`, `harness db
gc-blobs`) は repository / 関数が揃っているが wire-up は未実装。
post-Phase-16 で Phase 14 + 15 deferred CLI と一緒にまとめて land。
