## 4. Breaking changes / additions

### 4-α. `harness dashboard serve` 新 CLI

```
harness dashboard serve [--host 127.0.0.1] [--port 8787]
                        [--token-env <name>]
                        [--no-artifact-body]
                        [--max-inline-artifact-bytes 1048576]
                        [--cors-origin <origin>]
```

Phase 6 で導入された `harness dashboard export` (static export) と
並存。serve は live、export は cron / CI で固定 snapshot。

### 4-β. Auth fail-closed for non-local

`--host 0.0.0.0` + token 未設定 → 全 request に 401 を返す。warning が
起動時に出る。

## 5. Known limitations / Phase 13 への送り

### 5-A. Mutation endpoints は Phase 13

`POST /api/runs/:id/review` / `rerun` / `cleanup` / `pr` / backlog は
Phase 13 (mutation API + operation audit) で追加。Phase 12 server
skeleton はそのまま Phase 13 で再利用される (`--enable-mutation` flag
で POST routes を有効化)。

### 5-B. CSRF token は Phase 13 mutation で

read-only では CSRF は不要。Phase 13 で browser-based POST のため
CSRF token を導入。

### 5-C. HTML dashboard の polling refresh は client-side で簡略実装

Phase 12-6 では HTML の中に snapshot を embed しただけ。JS polling
の仕組みは Phase 12 では実装せず、operator が手動 reload で更新する。
Phase 13 / Phase 14 で client polling + WebSocket-light 経路を検討。

### 5-D. `/api/runs/:runId/artifacts` の content-type 推測

artifacts.content_type が NULL のときは application/octet-stream を
返す。これは Phase 8 ingest 経路で content-type 推測を強化する場面の
ヒント。Phase 14 で content-type DB-canonical 化検討。

### 5-E. shared maintenance lock の 423 Locked は未実装

design §E では timeout 30s で 423 Locked を返す予定だが、Phase 12 では
openManagedDb の default timeout 任せ (Phase 9 で 30s 設定済み)。
明示的な 423 化は Phase 13 mutation で必要なので、その時統合。

## 7. Phase 13 への接続

Phase 13 (mutation API + operation audit) は Phase 12 server を拡張:

- `--enable-mutation` flag を CLI に追加 (default OFF)
- POST routes を別 `mutationRoutes()` factory として追加
- CSRF token issuance を GET / (HTML dashboard) で配布
- operations table (schema v8) への記録
- 各 mutation endpoint で `(operation_type, target_id,
  idempotency_key)` で audit insert

Phase 12 の Bearer token gate / security headers / 405 method guard は
そのまま Phase 13 の mutation でも適用される (default OFF なら mutation
endpoint 自体 404)。
