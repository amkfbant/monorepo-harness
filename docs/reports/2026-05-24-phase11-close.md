## 4. Breaking changes

### 4-α. `review_proposals.lifecycle_status` の semantics

Phase 9-10 では `superseded_at` のみ。Phase 11 で `lifecycle_status`
列が追加され、`insertProposal` の supersede と `markProcessed` の両方で
更新される。**既存 row は `lifecycle_status='active'` で migrate**
されるため、Phase 10 close 後に supersede / processed になった行で
`lifecycle_status` が古い値 ("active") のまま残る可能性。

**Mitigation:**
- 新規 review 操作で自動更新される
- 手動 reconcile が必要なら `db migrate-legacy-lifecycle` を Phase 14
  で追加検討 (current は scope 外)

### 4-β. `harness review process --override` の新 flag

Phase 11-6 で `--override` / `--reason` / `--actor-reviewer` を追加。
default 動作は変わらず (override 未指定なら proposal 経由)。**override
指定時は rule snapshot の `allowedReviewers` を check** するため、Phase
11 default rule (allowedReviewers: []) では `system` が allowed リスト
に含まれず常に `UnauthorizedOverrideError`。Phase 14 で project profile
の rule から allowedReviewers を渡せるようになる。

### 4-γ. `harness review proposals` subcommand 新規追加

`harness review proposals list / archive / vacuum`。既存 command 名と
の衝突なし。

## 5. Known limitations / Phase 12 への送り

### 5-A. review rule の project profile 読み込み

Phase 11-3 `resolveEffectiveRule` は minimum = 常に DEFAULT_REVIEW_RULE
を返す。project profile YAML の `review:` section 解析は Phase 14
(project profile DB canonical 化) で実装。それまで Phase 11 runtime
は default rule のみ使う = 既存 latest-proposal mode の挙動。

### 5-B. `rejected_stale` lifecycle 発火経路

設計 §E1 では `rejected_stale` 状態を `maxAgeHours expired` で発火させ
る予定。Phase 11 default rule は `maxAgeHours` 未設定なので発火経路が
存在しない。Phase 14 で project profile rule 経由で driving される。
state machine 上は `vacuumOlderThan` が `rejected_stale` も eligible に
含めるため、Phase 14 で発火経路を足すだけで vacuum 側は変更不要。

### 5-C. review auto での reviewer_id 自動 fill

Phase 11-2 で ReviewerRepository.resolveOrThrow は実装したが、
`reviewer-agent` / `review auto` CLI は **まだ reviewer_id を proposal
insert 時に埋めない**。Phase 11 既存 review_proposals は `reviewer_id
IS NULL`。consensus evaluator は null reviewer の proposal を
group マッチから除外するため、consensus mode で reviewer_id 必須化する
ときは Phase 12 (dashboard) / Phase 13 (mutation API) で `review auto
--reviewer <id>` を強制する形にする。

### 5-D. consensus.summary に override actor / reason を完全 expose

Phase 11-6 で override 経路は consensus に override を渡すが、summary
JSON には override の actor / reason がそのまま入る (evaluateConsensus
が baseSummary に override をそのまま組み込む)。dashboard が Phase 12
で表示する経路は documented。CLI `harness review status` で
override section を表示する CLI は Phase 12 (dashboard read API) と
統合される。

### 5-E. state_version 全 writer 統合 (Phase 10 残作業 + Phase 11 でも未消化)

Phase 10-5 で review-process 関連 transition (`applyReviewDecision`,
`forceFailFinalize`) のみ state_version bump。Phase 11 でこの未消化を
解決する予定だったが、Phase 11 では `applyReviewDecision` 1 箇所のみ
拡張 (期待 state_version CAS optional 追加は Phase 10 post-close fix で
完了)。`setStatus` / `setSafetyStatus` / `cleanupRun` /
`createPullRequest` / `rerunFromReview` の bump 統合は Phase 13
(operations table) と合わせて再着手。consensus は当面 state_version
を invalidation trigger に使わない (proposal insert / override が
trigger)。

### 5-F. pr create / cleanup の post-run reservation (Phase 10-1 post-review P1)

Phase 11 では未着手。Phase 13 (mutation API + operation audit) で
operation_id の transaction flow と組み合わせて根本 fix する。

## 7. Phase 12 への接続

Phase 12 (dashboard serve + read-only API) は Phase 11 の output を表示:

- `review_consensus` の active row → dashboard `ReviewDashboardSummary`
  (pending / approved / changes_requested / rejected count)
- `review_overrides` → audit timeline 表示
- `review_proposals.lifecycle_status` → proposal カウント切り出し
- `run_review_rule_snapshots` → run detail で rule sha 表示

read-only API の各 endpoint で SQL 1 本にまとめられる shape:

```sql
SELECT r.run_id, r.status, c.status AS consensus_status,
       c.summary_json AS consensus_summary,
       (SELECT COUNT(*) FROM review_proposals p WHERE p.run_id = r.run_id AND p.lifecycle_status = 'active') AS active_proposals,
       (SELECT COUNT(*) FROM review_overrides o WHERE o.run_id = r.run_id) AS overrides
FROM runs r
LEFT JOIN review_consensus c ON c.run_id = r.run_id AND c.superseded_at IS NULL
WHERE r.run_id = ?
```

Phase 12-2 (snapshot API) で `DashboardSnapshot.review.consensusByStatus`
等を組み立てる。
