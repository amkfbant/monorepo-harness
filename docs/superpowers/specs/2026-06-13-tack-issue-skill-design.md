# tack-issue スキル設計

## 概要

ハーネス利用セッション中にエージェントが気づいた問題点を自律的に抽出し、
プロジェクト固有情報を完全に除去した上で、ハーネスの dev リポジトリに
GitHub issue を自動作成するスキル。

## 動機

ops モードで対象プロジェクトにハーネスを適用している最中、CLI の挙動や
policy 評価の不具合に気づくことがある。しかしその場で issue を書くと
対象プロジェクトの名前やドメイン用語が漏れやすい。このスキルはセッション
終盤に `/tack-issue` で呼び出し、問題の棚卸し・一般化・issue 作成を
フルオートで行う。

## 利用モード

- **ops モード**: 対象プロジェクトでハーネスを使用中。一般化（完全抽象化）を適用
- **dev モード**: ハーネス自体の開発中。自リポへの issue なので一般化をスキップ

モード判定は `git describe --tags --exact-match` の成否（ops = detached HEAD で
release tag に pin）またはディレクトリ規約（`ops/` vs `dev/`）で決定論的に行う。

## 起動と入力

```
/tack-issue          # 引数なし（デフォルト）
```

- 引数なしで実行。エージェントが会話履歴を走査し、ハーネスに起因する問題を
  自律的に抽出する
- 問題が見つからなければ「問題は見つかりませんでした」で終了
- 1 件以上あれば各問題を独立した issue として作成

## 抽出フロー

```
/tack-issue
  │
  ├─ 会話履歴を走査
  │   └─ ハーネスに起因する問題を抽出
  │       （CLI 動作・policy 評価・DB 操作・MCP・codex 連携・hitch など）
  │       （対象プロジェクト固有の設定ミスやユーザー操作ミスは除外）
  │
  ├─ 0 件 → 「問題は見つかりませんでした」で終了
  │
  └─ N 件 → 各問題について:
      ├─ モード判定
      │   ├─ ops → 完全抽象化を適用
      │   └─ dev → 一般化をスキップ
      ├─ ラベル自動判定（性質 + 領域）
      ├─ 重複チェック（既存 open issue と照合）
      │   ├─ 重複あり → スキップ（既存 issue URL を報告）
      │   └─ 重複なし → gh issue create
      └─ 作成した issue URL 一覧を報告
```

## 一般化ルール（完全抽象化）

ops モードでのみ適用。問題の本質だけ残し、具体例はすべて一般的な表現に置換する。

| 対象 | 処理 |
|------|------|
| プロジェクト名・リポジトリ名・組織名 | 除去（「対象プロジェクト」等に置換） |
| ファイルパス | 一般化（`services/payment/` → `services/<domain>/`） |
| テーブル名・サービス名 | 一般化（`orders_table` → `<table>`） |
| ドメイン固有の用語・ビジネスロジック | 問題の構造だけ残す |
| ハーネス側のコマンド・設定・エラーメッセージ | そのまま残す（issue の本体） |

## ラベル体系

全 issue に 3 ラベルを付与: 起源 + 性質 + 領域。

### 起源（全 issue 共通）

| ラベル | 説明 |
|--------|------|
| `tack-issue` | このスキル経由で作成された issue |

### 性質（1 つ選択）

| ラベル | 説明 |
|--------|------|
| `bug` | 期待と異なる動作 |
| `unexpected-behavior` | クラッシュはしないが挙動が不自然 |
| `missing-feature` | あるべき機能がない |
| `enhancement` | 既存機能の改善提案 |
| `error-message` | エラーメッセージが不明瞭・不正確 |
| `performance` | 遅い・リソース消費過大 |
| `docs-gap` | ドキュメントの不足・齟齬 |

### 領域（1 つ選択）

| ラベル | 説明 |
|--------|------|
| `policy` | policy 評価・スコープ検証 |
| `codex` | codex exec 連携 |
| `cli` | CLI の引数・出力・UX |
| `db` | DB / migration / import |
| `mcp` | MCP server / tools |
| `hitch` | hitch convergence |

ラベルが存在しない場合は `gh label create` で自動作成する。

## 重複チェック

```bash
gh issue list --repo amkfbant/monorepo-harness --label tack-issue --state open
```

既存 open issue のタイトルと照合し、同趣旨の issue が既にあればスキップして
既存 issue の URL だけ報告する。

## issue フォーマット

```markdown
## 概要
[一般化された問題の要約 -- 1-2 文]

## 再現状況
[どのような操作・状態で発生したか -- 具体的プロジェクト情報は除去済み]

## 期待される動作
[本来どうあるべきか]

## 実際の動作
[何が起きたか]
```

## 配置

```
monorepo-harness/.claude/skills/tack-issue/SKILL.md
```

プロジェクトスキルとして monorepo-harness リポジトリに同梱。ops / dev 両方の
checkout から利用可能。

## スコープ外

- issue 作成後のトリアージや優先度付け
- 既存 issue の更新・クローズ
- 対象プロジェクト側への issue 作成
- PR の自動作成
